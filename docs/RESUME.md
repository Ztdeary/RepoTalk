# 简历与面试材料

## 简历项目条目（4 条，建议全用，按岗位取 3 条）

**RepoTalk｜开源仓库代码问答系统（个人项目）**

- 基于 tree-sitter AST 按函数/类切分代码并保留 `file_path`/`start_line`/`symbol` 元数据，解决固定窗口切碎函数、答案无法定位的问题。
- 设计多路召回（向量 + BM25 + 符号精确匹配 + 逐字召回）+ 自写 RRF 融合 + rerank 精排：在 30 题代码定位数据集上，Recall@6 由纯向量的 **3.3%** 提升到 **98.3%**，MRR 由 **0.017** 提升到 **0.983**（`k=6`，脚本可复现，评测零 LLM 成本）。
- 用 RAGAS 四指标驱动 7 个检索参数联动调优，`context_recall` 由 **18.9% → 92.2%**、`faithfulness` 由 **28.8% → 93.3%**，平均提升 **+52pt**，验证瓶颈在检索层而非生成层。
- 用 arq + Redis 做异步解析，SSE 先推引用再逐 token 输出，检索期发心跳防代理断连，并实现结果缓存、访客配额、BYOK 白名单与 rerank 失败降级；Docker Compose 五容器部署并公网可访问。

> 措辞注意：不要写「Agent」。当前是**单轮 RAG 问答链路**，没有 tool calling / planning / 多跳。写 Agent 一定会被追问，答不上反而扣分。

## 30 秒讲法

1. **一句话**：把 GitHub 仓库按 AST 切成函数块，用多路召回 + RRF + rerank 找到相关代码，再让 LLM 只依据这些代码回答并给出文件行号。
2. **一个数字**：纯向量召回 3.3%，混合召回 98.3% —— 这就是我做这个项目最核心的发现。
3. **一个取舍**：rerank 只多赚 3 个点，但延迟翻倍；我知道它值不值，以及什么场景该关掉。

## 大概率被追问的 6 个问题（准备好答案）

1. **为什么用 RRF 而不是分数加权？**
   两路分数量纲不同（余弦距离 vs BM25 分），加权系数不可迁移；RRF 只看名次，换数据集不用重调。
2. **rerank 只提升 3pp，为什么还留着？**
   提升的是排序而不是召回：把定义块从第 2 名提到第 1 名，减少下游上下文噪声；延迟敏感场景可以按题型关掉。
3. **为什么不做 Agent / 多跳？**
   当前问题类型（定位、用法）单跳足够；加状态机没有收益。要做的话第一步是"先定位文件、再定位符号"的两跳检索。
4. **指标怎么算的？口径有什么问题？**
   文件级二值相关性（评测集只标到文件），先按文件去重防刷分；30 题、单仓库，统计噪声大；只衡量检索，不代表最终回答质量。
5. **单实例怎么扩容？**
   现在 BM25 在进程内存、`--workers 1`，不能多副本。第一步把 BM25 原料统一放 Redis/独立检索服务，再做索引版本化与原子切换。
6. **成本怎么控？**
   演示模式限 4 块上下文 + 320 输出 token，访客每日配额，BYOK 只允许白名单域名，rerank 失败降级而非重试风暴。
